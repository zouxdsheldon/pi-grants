# 工具数值校验报告 v2 · tools_validation
**校验对象:** pi-grants 站内 9 个新面板(文献计量 / 引文追踪 / 基因–疾病 / 临床试验 / 统计与样本量 / 差异表达 / 克隆设计 / 台账计算器 / 诚实外链)中**所有自己实现的数学**。

**为什么要做这件事:** 这些面板的公式全部是我在页面里用 JavaScript 手写的,没有调用任何成熟数值库。手写公式看上去对、跑得通,不等于算得对。所以本次用 **Python 的成熟库(scipy / statsmodels / Biopython)独立算一遍**,再把站内函数在**完全相同的输入**上跑一遍做逐项比对。

**方法上的两条硬约束(否则这份报告没有意义):**
1. JavaScript 那一侧**从不读取** Python 参考值 —— 两边各自独立算,只在最后比。
2. 每条比对都做了**反向验证**:故意把公式改错,确认比对确实会失败。只会通过的检查不算检查。

### Tm 这一项要说清楚:公式对 ≠ 结果准
站内 Tm 用的是**含盐校正的经验近似式**,不是最近邻(nearest-neighbour)热力学模型。上面校验的是"代码有没有正确实现它自称的那个公式",这一点通过了。但和更严谨的模型比:

| 模型 | 同一条 30 nt 序列的 Tm |
|---|---|
| 站内经验近似式 | 67.09 ℃ |
| Biopython 最近邻模型 `Tm_NN` | 67.32 ℃ |
| Biopython GC 经验模型 `Tm_GC` | 64.50 ℃ |

**结论:** 三者相差可达 2–3 ℃。站内数值**可以用来排序和粗筛引物**,但**不要**拿它直接定退火温度 —— 定退火温度请用厂商计算器(与你实际用的缓冲体系匹配)或做温度梯度 PCR。这一句已同步写进面板提示。

## 三、反向验证:故意改错,确认能被抓到

如果一份校验只会通过,它什么也没证明。以下每一条都是把页面里的公式改错、重跑比对、确认结果发生变化:

| 注入的错误 | 是否被抓到 |
|---|---|
| RCF 常数 1.118×10⁻⁵ → 1.118×10⁻⁴ | ✅ 抓到 |
| ΔΔCt 倍数 2^(−ΔΔCt) → 2^(+ΔΔCt) | ✅ 抓到 |
| Beer 定律漏掉光程 l | ✅ 抓到(见下方说明) |
| Tm 盐校正系数 41 → 51 | ✅ 抓到 |
| 稀释公式 C2·V2/C1 → C1·V2/C2 | ✅ 抓到 |
| 多重校正方法名写错 | ✅ 抓到(见下方缺陷) |

**其中一次"漏抓"是我自己的测试没写好,不是代码对:** 第一轮 Beer 定律测试我把光程设成 1 cm —— 而 l=1 时,漏掉 l 这一项结果完全不变,所以再错也测不出来。把光程改成 0.5 cm 后立刻抓到(38.43 → 19.21 µM)。**教训:测试输入必须让被测项目真正参与运算。**

## 四、本次校验发现并修复的真实缺陷

**缺陷:BY(Benjamini–Yekutieli)校正列显示的其实是 BH 的值。**

差异表达/统计面板给用户四列校正结果:BH、BY、Bonferroni、Holm。但底层 `adjustP()` 函数**根本没有 `"by"` 分支** —— 传进去的 `"by"` 落进了最后的 else,也就是 BH 分支。结果:BY 那一列和 BH 一列数字完全相同,而用户会以为自己看到的是更保守的 BY 校正。这在实际使用中会导致**把相关检验下的假阳性风险低估**。

**修复两处:**
1. 补上真正的 BY:在 BH 的基础上乘调和数 c(n)=Σ(1/i),i=1..n —— 这是允许检验间任意相关时的正确形式。修复后与 `statsmodels` 的 `fdr_by` 逐位一致(最大差 2.22e-16)。
2. 未知方法不再静默回退:`adjustP()` 现在对无法识别的方法名**直接抛错**。原来的静默回退正是这个 bug 能藏这么久的原因 —— 错误的方法名不会报错,只会安静地给出另一种方法的结果。

**缺陷二:序列面板对上千 nt 的序列也照样给出 Tm。**

Wallace 式与盐校正近似式都是**为寡核苷酸(引物、探针)推导的**。但面板此前对任何长度都照算 —— 冒烟测试里一条 1008 nt 的 GAPDH CDS 得到了"Tm 86.9 ℃"这样一个看起来很像样、实际没有物理意义的数。

**修复:** 序列 >60 nt 时 Tm 一栏显示"—",并说明为什么不给数、以及要引物 Tm 应该只贴引物那一段。**给出误导性的数,比不给数更糟。**

**这两个缺陷都已加入自动断言**(`tests/assert_new.js`):BY 不得等于 BH、未知方法必须抛错、长序列不得给 Tm、短序列必须带"不要用它定退火温度"的告诫。四条断言各自做了反向验证,确认改坏后都会失败。

## 五、这份报告不能证明什么

说清边界,免得被当成"全站已验证":

- 只覆盖了**站内自己实现的数学**。面板里通过外部 API 取回的数据(PubMed、Europe PMC、ClinicalTrials.gov、MyGene 等)其**正确性由数据源负责**,本站不做二次核对,也无法核对。
- Tm、A260 换算系数、缓冲液计算等都是**教科书经验式**,已在上文标注适用边界;它们对不对是"实现是否忠于公式"的问题,不是"公式在你的实验条件下准不准"的问题。
- 统计面板做的是**常规参数与非参数检验**,不含混合效应模型、生存分析、多因素校正设计。数据结构复杂时请用 R/Python 正式分析。
- PCA 面板的方差解释率已与 `scikit-learn` 一致,但**载荷向量的符号**在不同实现间可以整体反号 —— 这是 PCA 本身的性质,不是错误。
