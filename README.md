# Grants Finder Pro — 早期 PI 资助 / 职位 / 文献追踪站(开源模板)

一个**纯静态、自动更新**的网站模板,把早期研究者找钱、找教职、追文献这三件事放在一个页面里。
**任何人 fork 后填自己的信息即可使用** —— 个人信息只存在使用者自己的浏览器里,不进仓库、不上传服务器。

在线示例:fork 后你的地址是 `https://<你的用户名>.github.io/<仓库名>/`

---

## 三分钟上手

**只是想用一下(不部署)**
打开站点 → 右上角 **✏️ 填写/修改档案** → 三步填完。资格自查、资助匹配排序、文献相关性会立刻按你的信息重算。
不确定要填什么,先点 **👤 载入示例档案** 看效果。

**想要属于自己的一份(含每日自动抓取)**

1. Fork 本仓库。
2. 仓库 **Settings → Pages → Source 选 `GitHub Actions`**。
3. 仓库 **Settings → Actions → General → Workflow permissions 选 `Read and write permissions`**(让定时任务能提交数据)。
4. **Actions 标签 → `Update grants data` → Run workflow** 跑一次。十分钟后站点就活了。

### `data/funds.json` 的规则语法

每个基金一条记录,`rules` 是一个数组,全部通过才判「现在能投」:

```json
{
  "id": "k99",
  "name": "NIH K99/R00 (Pathway to Independence)",
  "flag": "🇺🇸", "agency": "NIH", "region": "美国",
  "url": "https://grants.nih.gov/...",
  "summary_zh": "博后→独立 PI 转轨奖。",
  "write_key": "k99",
  "rules": [
    {"field": "career_stage", "op": "in", "value": ["postdoc"],
     "pass_zh": "处于博士后阶段", "fail_zh": "当前身份为「{v}」,K99 要求申请时仍是博士后"},
    {"field": "postdoc_years", "op": "lte", "value": 4,
     "pass_zh": "博后 {v} 年,在 ≤4 年窗口内", "fail_zh": "博后已 {v} 年,超出窗口"}
  ]
}
```

算子:`eq` / `ne` / `gte` / `lte` / `in`(值在列表里)/ `has`(多选字段包含某项)/ `nhas`(不包含)/ `truthy` / `falsy`。
`{v}` 会替换成用户填的值。`write_key` 指向写作面板里对应的草稿模板。

### 资格判定的诚实边界

- **只用你填过的字段判定。留空 = 显示「信息不足」,绝不猜成「能申」。** 一个字段都没填时,所有基金一律显示「信息不足」,不给任何假阳性。
- 规则是各基金公开条款的**简化版**。窗口延期、机构豁免、特殊通道、逐年变动的细则都没编进去。
- **最终一律以官方 NOFO / 申报指南为准。** 每条判定旁边都有官方链接,请点进去核对。
- 联邦机会卡片上的资格徽章更弱:Grants.gov 的资格字段是**机构级**的,公民身份写在 NOFO 正文里,数据里根本没有。所以那里只用「数据里真有的字段 + 你填的职业阶段」做粗筛,标注为启发式。

- **美国联邦机会** `data/grants.json` — `scripts/fetch_grants.py` 抓 Grants.gov,每日刷新,剔除过期,按截止排序。抓取在 GitHub 的服务器上完成,与你本地网络无关。

- **文献** `data/papers.json` — `scripts/fetch_papers.py`,六源抓取,详见下方「文献追踪面板」章节。
- **截止日历** `data/grant_deadlines.ics` — `scripts/build_ics.py`,滚动两年不过期,可用 webcal 订阅。
- **每日摘要与 RSS** — `scripts/build_digest.py` 生成 `digest.html` 与 `feed.xml`。

不想等定时任务:**Actions → 选对应 workflow → Run workflow**。

### 调整联邦机会的搜索范围

编辑 `scripts/fetch_grants.py` 顶部的 `KEYWORDS` 列表,以及 `HI`/`MID`(相关度打分词)。push 后下次运行生效。

### 从 Pivot-RP 导入(合法用法)

Pivot-RP 没有面向个人的 API,且其编辑描述是 Clarivate 版权内容,不能整段搬运。
把它当**发现工具**,导出后只并入**事实字段 + 官方链接**:

1. Pivot-RP 里勾选想要的机会 → **Export**(导出 CSV)。
2. 放到 `data/pivot_export.csv`。
3. 运行 `python3 scripts/import_pivot.py data/pivot_export.csv`。
4. 脚本只保留项目名/资助方/截止日/金额/链接;描述留空,请用你自己的话补 `note`。
5. `git add -A && git commit && git push` → 自动重新部署。

**自动归国**:按资助方名判定国家/地区(NIH→🇺🇸、ERC→🇪🇺、Wellcome→🇬🇧、NSFC→🇨🇳、
JSPS→🇯🇵、A*STAR/NRF→🇸🇬、NHMRC→🇦🇺、CIHR→🇨🇦、HFSP→🌍…),识别不到的进兜底分区。
补规则编辑 `scripts/import_pivot.py` 顶部的 `REGION_RULES`。

没有 Pivot 订阅完全不影响使用 —— 联邦数据源和文献追踪都不依赖它。

## 📚 文献追踪面板 — 算法与已知局限

### 数据来源(6 源)

| 源 | 覆盖 | 取什么 | 已知局限 |
|---|---|---|---|
| **PubMed** (E-utilities) | 生物医学期刊 | 标题/摘要/作者/单位/MeSH | 只收录已被 PubMed 索引的期刊;新刊/中文刊缺失 |
| **Europe PMC** | PubMed 超集 + 全文 + 被引数 | 同上 + `citedByCount` + OA 全文链接 | 被引数只统计 Europe PMC 内部的引用,**系统性低于 Web of Science / Scopus** |
| **Europe PMC 预印本** (`SRC:PPR`) | bioRxiv/medRxiv/Research Square | 预印本记录 | 索引有滞后 |
| **bioRxiv API** | bioRxiv 全量 | 按日期窗翻页 + 本地词库过滤 | 官方 API **不支持关键词检索**,只能全量翻页(每页 30 条);详见下方"截断" |
| **arXiv** | q-bio 等 | 少量计算/建模类 | 生物学论文极少投 arXiv,命中量本来就小;官方要求请求间隔 ≥3 秒 |
| **Crossref** | 全学科 DOI 元数据 | 补充非 PubMed 期刊 + `is-referenced-by-count` | `query.bibliographic` 是**宽松相关性匹配**,返回大量弱相关项 —— 全部要再过本站打分器 |

**没用 OpenAlex**:需要 API key,本项目未获授权,故被引数改由 Europe PMC + Crossref 提供。
**没用 Web of Science / Scopus**:需付费订阅,无免费接口。

### 相关性评分(完全透明,面板里每个分数可点开看构成)

分数 ∈ [0, 1],由四部分加权求和,权重写在 `data/interests.json` 的 `score_weights`:

1. **核心词命中**(`core`)—— 你方向里的定义性术语(如 `zswim8`、`tdmd`),权重最高
2. **外围词命中**(`peri`)—— 相关但不特异的词(如 `mirna`、`ampk`)
3. **TF-IDF 余弦**—— 论文文本与该方向词库的向量相似度,捕捉没被词表穷举的表述
4. **加成/惩罚**—— 标题命中乘以 `title_multiplier`(标题里出现比摘要里出现更说明问题);命中 `exclude` 词(如纯植物学、纯临床流行病学语境)按 `exclude_penalty` 扣分

得分 < 0.12 的记录直接丢弃。剩下的按 `bands` 阈值分成 🟣高 / 🔵中 / ⚪低。

**这不是"AI 判断"**,是可复算的字符串匹配 + 向量相似度。你不同意某篇的分数,改 `interests.json` 的词库即可,下次抓取立刻生效。

### 三类标记怎么来的

| 标记 | 判据 | 局限 |
|---|---|---|
| 🔥 **Hotspot** | 引用速率(被引/月)+ 新鲜度(≤60/180 天)+ 预印本已被期刊接收 + 引用加速度 | **引用加速度需要历史快照**:每天抓取会把当天被引数存进 `data/citation_snapshots.json`,累积 ≥7 天后才能算加速度。刚部署时这一项恒为空,面板会如实显示"快照天数不足"。另:新论文被引数天然接近 0,所以"新鲜度"权重是必要的补偿,但也意味着**高分 ≠ 重要**,只是"值得现在看一眼" |
| 🕳️ **Gap** | 正则匹配作者自己写的空白句("remains unclear"、"has not been investigated"、"lack of evidence" 等) | **只能抓到作者明写的空白**。真正的空白往往没人写出来 —— 这是提示,不是空白检测器。面板里**原句照抄展示**,你自己判断 |
| ❓ **Question** | 正则匹配 future work 句式("future studies should"、"it will be important to" 等) | 同上;另有 `limitation` 句作为附加证据展示 |

三类标记都**不做模型改写**,展示的是论文原句,可点 DOI 回原文核对。

### 期刊层级 T1–T4 是自建代理,不是影响因子

JCR 影响因子是 Clarivate 的版权数据,没有免费接口。本站按**公开可查的刊名**做了一个四级分层(`journal_tier()` 里的名单是硬编码的、可读的、你可以直接改)。

- 它**不是** IF,不要写进任何正式材料
- 名单不全,没收录的刊一律归 T4 —— **T4 不代表期刊差,只代表不在名单里**
- 预印本单独标 `preprint`,不参与分层

**已修的大坑(留作记录):**早期 `journal_tier()` 用**子串**匹配名单,后果很荒唐 ——
名单里的 `"cell"` 命中了 *Tissue and Cell* / *Cells* / *iScience*,`"rna"` 命中了
*Inte**rna**l and emergency medicine*(靠 "internal" 里的 rna 进了 T3)。873 篇语料里
**149 篇被误标 T1**。现在改成:刊名先归一化(小写、去副标题 `: …`、去尾部括注、去标点),
再与名单**整名相等**才算命中;跨库刊名写法差异用 `TIER_ALIAS` 别名表对齐;预印本服务器
因为刊名字段带长后缀,仍按前缀识别。修正后 T1 = **2 篇**(诚实值),321 篇论文的
`tier` 被重写。改名单请**加名字**,不要放宽匹配规则。

### bioRxiv 扫描是**有意截断**的

bioRxiv 官方 API 不支持关键词检索,只能按日期窗全量翻页,每页 30 条 —— 60 天窗口约 1.2 万篇,要翻几百次。为了不让每日 Actions 卡死,设了**时间预算 + 页数上限**,超出即停,并在 `data/papers.json` 的 `meta.biorxiv_scan` 里**如实记录**扫了多少 / 总共多少 / 是否截断。

最新的预印本排在前面,所以截断丢的是**较旧的**而不是最相关的;Europe PMC 的 `SRC:PPR` 源提供互补覆盖。

### 去重

三级:归一化 DOI → PMID → 标题相似度(difflib ≥ 0.92,按标题前 12 字符分桶避免 O(n²))。合并时保留字段最全的版本,来源标签取并集,被引数取最大值。

**已修的坑**(留作记录):预印本与其期刊正式版合并时,布尔字段 `preprint` 曾被错误覆盖成 `True`,导致正式期刊论文被标成预印本 —— 布尔字段判空不能用 `not x`。

### 合作者网络的局限

作者姓名按**姓 + 名首字母**匹配。这意味着:同名不同人会被合并;大型联盟论文(几十个作者)会产生大量虚假边。网络图只用于**发现潜在合作方向**,不能当作可靠的社会网络分析。

### 🔎 深读拆解 —— 把「找到」变成「读懂」

每张文献卡片右下角的 **🔎 深读拆解** 会拉出一个抽屉,里面 6 个分区。
**整层不调用任何大模型**,全是离线可核验的计算 —— 屏幕上每一句你都能当场对着原文查。这是有意的取舍:宁可少给几个结论,也不要"读起来很有道理但查不到出处"的句子。

由 `scripts/analyze_papers.py` 生成(写回 `data/papers.json` 的分析字段),`scripts/fetch_citenet.py` 生成 `data/citenet.json`。

**① 结构化拆解.** 摘要切成 背景 / 方法 / 结果 / 结论。**来源标签是硬要求:**
- 原文自带 `BACKGROUND:` `METHODS:` 这类标签的 → 标 **原文标注**(权威,直接采用)
- 没标签的 → 用句式规则推断 → 标 **规则推断**(会错,尤其是叙述性摘要)

**已知局限:**本语料只有少数论文的摘要是出版社结构化标注的,绝大多数是推断结果。看到"推断"标签请自己核一眼。

**② 方法与实验体系.** 术语表匹配,**每个命中都挂着触发它的那句原文**(悬停可见)——这样你能立刻判断是真做了这个实验,还是只在讨论里提了一句。术语用词边界正则匹配(早期版本 `CLASH` 这类缩写会匹配进普通单词内部,已修);同义拼写(如 `scRNA-seq` / `single-cell RNA-seq`)归一到同一个方法,否则会把一个方法数成两个。

**③ 可复用句式.** 抽取的是**未经改写的原文句子**,按功能分类(研究空白 / 方法陈述 / 意义影响 …)。
⚠️ **这些句子的著作权属于原作者。** 面板里也写了:看句子的**结构**,用自己的话重写,**不要整句照抄进申请书** —— 那是抄袭,而且评审用的查重系统查得出来。

**④ 新颖度审计(三分量摊开,可核对).** 分数 = 内容距离 + 罕见术语占比 + 首现术语新鲜度,三项都单独显示条形图和百分位。

**两个必须知道的校正:**
- **年份队列相对化.** 最初的实现里,平均新颖度随发表年份单调下降 —— 纯粹是"首现术语"分量的语料位置假象:早期论文占了首次出现的位置,于是去年的论文看起来比这个月的更新颖。现在**三个分量都在同一发表年份的队列内做相对化**,抽屉里会显示队列大小和你这篇在队列里的百分位。
- **分档按语料分位数校准.** 最初的固定阈值把绝大多数论文都划进"高",等于什么都没区分;现在切点取自语料分位数,写在 `data/papers.json` 的 `meta.analysis.novelty_cuts` 里。

**它衡量的是"措辞离既有文献有多远",不是"科学上有多重要"。** 一篇用全新词汇包装旧想法的论文会得高分;一篇用朴素语言做出重大发现的论文会得低分。抽屉里也这么写着。

**⑤ 引用邻域.** 只画**两端都在本语料内**的引用边 —— 因为只有这样的边你才能在站内点开核对;指向语料外的边无法验证,画上去只是装饰。

**已知局限:边很稀疏。** 本语料是近期时间窗切片,成员之间还没来得及互相引用,这是**预期结果,不代表这些论文影响力低**。面板顶部的概览卡直接把查询数 / 边数 / 失败数摊开写。另外:**预印本没有 PMID,不在图内**。

**⑥ 相关性怎么算出来的.** 命中词、TF-IDF 余弦、各分量权重的明细表。若触发了**主题锚点缺失**(没有任何核心词、只靠边缘词和相似度噪声凑分),这里会显示告警并说明该记录的档位被压低了 —— 早期版本会让一篇完全跑题的论文靠边缘词进"中等相关",现在有这道闸。

### 全局搜索(跨 5 个库)

顶部搜索框一次查 5 个源:联邦机会 / 各国 PI 资助 / 学术职位 / 文献 / 期刊。

**匹配规则(面板里也写着,不是黑盒):**
- 查询按空白切成若干 token,**每个 token 都必须命中**(AND,不是 OR)
- 命中方式是**子串包含**,不做词干化、不做同义词扩展、不做拼写纠错、不做语义检索
- 大小写不敏感;命中片段在结果里高亮
- 每组最多显示 12 条,超出部分显示"另有 N 条,点这里到对应面板"

**为什么不上语义检索:**要么调外部模型(违背本站"每个数字都能离线复算"的原则),要么在
浏览器里塞一个向量模型(几十 MB,为一个单人站点不值)。子串 AND 的行为是**可预测**的 ——
搜不到就是真的没有这个字符串,而不是"模型觉得不相关"。无结果时面板会**把这条规则原样打出来**
并回显你的查询词,让你知道该怎么改词。

搜索状态写进 URL 的 `?q=`,可以直接把一条搜索发给别人。

### 期刊查选面板(`data/journals.json`)

由 `scripts/build_journals.py` 从 `data/papers.json` 的 873 篇语料聚合而成,**473 本刊**。

**三条硬性诚实约定,面板顶部用醒目色块写着:**

1. **所有统计都是"本语料内"的,不是该刊的全库统计。** 本站语料是按你的研究方向 + 近期
   时间窗切出来的一片,`n=12` 意思是"这 12 篇符合你方向的论文发在这本刊",不是"这本刊
   一共发了 12 篇"。拿它当投稿参考可以,拿它当期刊评价**不行**。
2. **不提供也不显示影响因子。** JCR IF 是 Clarivate 的版权数据,没有合法免费接口。
   宁可不给,也不给一个来路不明的数。
3. **样本太薄的刊直接标 `thin`,不给百分比。** 阈值 `MIN_N=3`,473 本里有 **411 本**
   被标 thin。这些刊在表格里显示"样本不足",而不是显示一个由 1 篇论文算出来的
   "100% 开放获取"。**分母是 1 的百分比是噪声,不是信息。**

每本刊给出:语料内篇数、近三年占比、开放获取占比、新颖度中位数、年份分布、主攻方向指纹
(按你在 `data/interests.json` 里定义的方向做的柱状条)、层级、以及可展开的**代表论文**
(点开直接跳文献面板对应卡片核对)。支持按刊名/方向/层级筛选,列头可排序。

"不报错":

- 工具卡上的每个数字都要**用同一份数据独立复算一遍**再比对 —— 防止卡片和面板对不上

没查规则说明;一条只查了筛选后的行数,没查渲染出来的百分比。两条都已收紧,记在这里
是因为**漏掉的负控比失败的负控更值得记录**。

### 每日自动化

`.github/workflows/update.yml` 每天跑一次:抓资助 → 抓职位 → 建日历 → **抓文献 + 存被引快照** → **离线分析(分段/方法/句式/新颖度)** → **建引用网络** → **跑前端测试** → **生成摘要页 + RSS**,有变化就自动提交。

引用网络那步有**全局墙钟预算**(`--budget`,秒)。线上出现过连接挂起把整轮任务拖到两小时无输出的情况,所以现在超预算就把已抓到的部分写出去并退出 —— 定时任务宁可数据不全,也不能挂住。抓取本身是小并发线程池 + 短超时,因为实测单篇延迟从 1 秒到 11 秒不等,挂起的连接靠并发摊薄。

- 摘要页:`digest.html`(可直接打印/转发)
- RSS:`feed.xml` —— 加进 Feedly / Inoreader / NetNewsWire 即可每日推送
- **不做邮件推送**:发信需要 SMTP 账号密码,放进公开仓库不安全;RSS 效果相同且零凭据

## 🧭 内联帮助 · 统一筛选 · 诚实空结果(2026-08 改版)

### 为什么示例按钮是「可点」的,不是截图或文字

每个工作面板顶部有一条帮助带(`.hstrip`,默认折叠,展开状态存 `localStorage`),结构固定三段:

1. **这个工具解决什么问题** —— 一句话,用第二人称写「你想回答的问题」,不写功能名词
2. **三步用法** —— 具体到点哪个控件
3. **可点示例** —— 按钮上写着实测命中数,点下去直接把筛选器设成示例值并重新渲染

第 3 点是关键设计。截图会过期,写死的数字会在第二天数据更新后变成假话。所以示例的命中数由 `exCount()` **实测**:临时清空该面板筛选 → 套用示例值 → 走**真实渲染路径** → 读回面板自己上报的行数 → 还原用户原来的筛选状态。

- 不另写一套筛选逻辑来算命中数 —— 平行实现迟早会和页面显示的结果对不上
- 面板若走了 early-return(数据还没加载完),`countOf()` 返回空,按钮上就不显示数字 —— **宁可不显示,也不显示错的**
- 侧栏那三个复选框筛选(资助类型 / 相关度 / 截止)不是 DOM 控件,状态在 JS 变量里。示例要能驱动它们,所以有一层虚拟筛选 `VFILT`(每个面板一组 list / set / clear 函数),`ctlSet()` 会路由过去;实测命中数前后用 `snapVirtual()` / `restoreVirtual()` 快照还原,不会把你自己勾的框洗掉

### 生效中筛选芯片

每个工作面板帮助带下面是芯片栏(`#chips_<panel>`):

- 逐条列出**生效中**的筛选条件,每条可单独 `×` 撤销
- 「清空全部」一键回到全量
- 右侧「显示 N / 共 M」

排序控件在 `PFILT` 里标了不计入筛选 —— 排序不减少结果,算成"生效中的筛选"会误导。侧栏复选框通过 `VFILT` 合并进来,所以勾了 3 个资助类型时芯片栏会如实显示 3 条,而不是"未设置筛选"。

### 金额显示缺陷(字符串真值)

Grants.gov 导出里,金额缺失不是 `null`,而是字面量 `"none"` / `"None"` / `"0"`。这些在 JS 里**全是真值**,所以卡片上原来的 `amount || "见 NOFO"` 兜底从来没触发过,1153/1720 张卡片印着「金额上限: none」——看起来像数据,其实是占位符;数值排序键也会拿到非数字。

修法是三个函数:`amtMissing()` 判缺失、`amtNum()` 强制返回数字给排序、`amtTxt()` 显示「见 NOFO 原文」并加缺失样式。**卡片上写明这是数据源没给,不是 0 元。**

### 精选面板可信度分层

`data/curated.json` 的 167 条不是同一个可信级别:

| 档 | 条数 | 含义 |
|---|---|---|
| `official` 已核实(官方 NOFO) | 3 | 逐条对过官方公告 |
| `pending` 待核实(官方链接) | 36 | 有官方链接、未逐条核对 |
| `pivot` 来自 Pivot 导出 | 128 | 批量导出,未核实 |

原来这个分层在数据里但筛不出来 —— 未核实的条目在屏幕上和已核实的长得一样。现在有 `cverify` 下拉,`verifyKey()` 把自由文本归一成三个键。

### 空结果的诚实处理

筛到 0 条不留白页,而是列出**是哪几个条件共同把结果筛没的** + 一键清空。

期刊面板要特殊处理:它的结果区是 `<table>`,往里塞 `<div>` 会被浏览器 foster-parenting 踢出去,所以另起一个 `#jempty` 兄弟容器 —— 但这样它就不会被下一次渲染覆盖,必须显式清除。清除逻辑用 `NORES_IN` 记账(只清自己写过的容器),不去读 `firstElementChild` 的 class(表格或非浏览器宿主上会失效)。

### 本轮测试增量

`tests/run_portal_tests.py` 断言 540 → **658**,新增覆盖:

- 每个工作面板都有帮助条,且每条都带示例
- 每个示例指向的控件**真实存在**,设的值**真在该控件的选项里**
- 示例按钮上写的命中数 == 渲染后实际显示的行数
- 芯片栏反映得出侧栏那三个非 DOM 筛选
- 「清空全部」后每个面板回到全量条数
- 0 结果时回显是哪些条件造成的,且给得出退路
- 金额缺失渲染成「见 NOFO」而不是把占位符当钱印,且排序键必为数字
- 可信度筛选逐档条数与数据重算一致,且确实缩小结果

负控 21/21 全部被抓到。本轮负控暴露的**两个真缺陷**(不是测试问题):

1. 期刊面板零结果框不会被下一次渲染清掉 —— 见上文 `NORES_IN`
2. 测试桩的 `getElementById` 对**任意** id 都凭空造一个元素,于是"绑到拼错的 id"这类 bug 全部隐形。已改成:只有页面里真实存在的 id 才返回元素(id 集合由 fixture 传入,运行时才创建的容器按前缀白名单放行)

> 负控里有一次注入打进了排序函数而不是渲染函数(两者读同一个控件),抓是抓到了,但抓到的是"筛选没绑上"而非目标缺陷 —— 记在这里,不粉饰。

**改断言的规矩不变:** 加了新行为就要加断言,加了断言就要写一条负控证明它抓得住。跑负控后文件必须字节级还原。
